# 前后端一体化演示路线

目标是做出可以现场演示、结果可核查的 Knowledge CI 工作台：修改知识后，观众能看到版本变化、自动评测结果，以及支持判断的原始证据。本路线以验收结果安排依赖，不承诺未经估算的完成日期。

真实项目文档验收和 B1 只读管理 API 已完成。前端已授权恢复 B2，V3 生命周期与变更视图已实现，原 V2 静态演示保留；下一批 B3 补 V4 评测导览。B4 HTTP 写交互、B5 MCP 均未实现，没有公开 live 部署。版本仍为 `0.1.0` prepared，未创建 tag、PR、main 合并或 PyPI 发布。

## 真实文档验收结果

2026-11-13 的隔离运行使用现有 `docs/auto-evaluation.md` 和 `docs/acceptance.md`，导入 11 个知识单元。评测集在首次发布后冻结，共 4 条用例，包含多证据与无答案问题。正向变更、故障注入和恢复均通过正式 CLI 导入触发自动评测。故障时 Recall@5 从 1.0 降到 0.666667，恢复后回到 1.0；失败记录保留，重复导入不产生新任务。

这是项目文档的真实验收，覆盖本机 SQLite 与 lexical 检索。它不证明生产业务效果、模型语义理解、生成答案正确性或完整 Agent 任务成功率。该次验收使用默认绝对质量门禁，没有自动接受基线或宣称已完成 delta 回归。

B1 提供任务、revision、lineage、文档版本 Diff 与精确历史证据的只读契约。B2 已将这些数据接入实时页面，支持任务过滤、分页、手动刷新和 hash 导航，不再停留在静态 fixture。任务详情的聚合 metrics／checks 已有初步展示，可比结果、用例级诊断与完整导览仍属于 B3。

## 产品特色围绕变更展开

工作台从一次知识变更进入，展示该次变更的 revision、关联任务和固定评测集。用户先回答“这次改动是否通过”，再查看相关的知识版本与引用。

- **结果能回到证据**：从评测任务进入版本 Diff，再定位知识单元与原文范围，显示来源、版本及持久化当前状态；该状态不冒充任务当时的 as-of。
- **失败与修复都有记录**：现场展示一次正常更新、一次质量下降和一次修复。修复新增任务，不覆盖失败报告。
- **知识有时间边界**：查看确切文档版本及 lineage 历史，区分 stale、superseded 和退役内容，不用最新正文替换历史证据。
- **指标有适用范围**：保留评测时间、数据集版本及配置／知识指纹。B3 对照前还需检查策略、检索参数和时间口径，引用完整不等于答案正确，相关变化也不自动等于因果归因。

视觉上保留现有 V2 基础，先保证每个状态能解释、每个数字有来源，再做动效和外观润色。

## 本机演示与下一批

启动命令、安全接线和验证步骤见 [本机只读工作台](live-workbench.md)，HTTP 契约见 [只读管理 API](management-api.md)。先运行真实文档验收脚本，再把它实际输出的唯一运行目录交给启动器，不固定某台机器的路径或凭据。Vite Node 与 backend 保存临时 key，浏览器只发同源 GET；preview／dist 不提供 dev proxy。

B2 已处理 loading、空列表、安全错误、读取重试和完整任务状态，`null` 不当作零；请求用 Abort 与 sequence 防止旧响应覆盖。页面保留任务指纹和确切历史证据，单元 status 仍是持久化当前缓存。原文范围按 Unicode code point 解释，原文作为未受信文本展示。

B3 将补可比结果和用例级诊断，不能把现有聚合汇总称作完整 V4。B2 已完成真实浏览器最短导航与回归验收；浏览器没有逐项人工检查全部状态和移动端尺寸，公开服务也未部署。

## 展示安全与后续能力

自动评测内部报告当前不保存 query 或源全文。B1 不暴露 SQLite 表、私密评测集、绝对路径或任意 payload，原文选段仅在认证后的 evidence 端点明确返回。用例级失败诊断需返回必要的标识、预期 lineage 与证据定位，不默认导出原始问题。当前导航提供定位线索，不宣称自动因果归因。

当前同步评测会增加变更耗时。现场演示继续使用单库、小规模评测，不把它包装成异步生产服务。后台调度、真实 embedding provider、向量／混合自动评测和 Agent 答案质量评测，分别补 provider 配置、隐私边界、成本与验收数据后再推进。

外部演示默认使用可公开的项目文档和独立副本；用户业务库只用于经授权的私密验收。公开部署前还需确认认证、数据脱敏、运行可恢复性和服务暴露边界。
